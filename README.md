# 📚 电商智能客服问答助手（RAG）

基于 **RAG（检索增强生成）+ Agent 工具调用** 的智能客服系统，面向 **小米商城数码产品** 多场景：售前商品咨询（价格 / 参数 / 选购对比）、订单物流查询、售后政策与进度查询——上传产品说明书 / 售后政策等文档构建向量知识库，用户提问后先检索相关知识片段，再交给大模型生成有据可依的答案。

## ✨ 核心功能

- **智能问答**：混合检索（BM25 关键词 + 向量语义 双路召回）+ LLM 生成，答案附带来源引用
- **实时价格查询（Redis 工具）**：动态价格走 Redis 缓存层（准实时，每 4 天自动刷新），静态知识走 RAG 知识库，数据分层互不污染
- **订单 / 物流查询**：订单状态、物流进度、发货签收 → 自动路由到订单工具
- **售后进度查询**：退换货 / 维修进度 + 售后政策问答
- **商品图片识图（多模态）**：上传商品图，视觉模型识别品牌/名称/关键参数，拼进问题再走 RAG 回答
- **知识库管理**：上传 PDF / TXT / MD / Word / Excel / HTML 等格式，自动分块、向量化入库，支持全文检索
- **多轮对话与会话管理**：历史会话按用户隔离，可切换/续聊
- **用户体系**：注册 / 登录 / JWT 鉴权 / bcrypt 密码加密 / token 7 天有效（localStorage 持久化，过期自动跳登录）
- **成本监控面板**：LLM token 用量与费用统计
- **一键体验（游客模式）**：免注册直接进入问答，方便演示

## 🧰 技术栈

| 层 | 技术 |
|---|---|
| 后端 | FastAPI + SQLAlchemy + SQLite |
| 前端 | Vue 3 + Vite（单页应用） |
| 向量化 | sentence-transformers（BAAI/bge-small-zh-v1.5，本地 Embedding） |
| 检索 | rank-bm25（关键词）+ Chroma 向量库（语义）混合召回 |
| 精排 | 阿里云百炼 qwen3-rerank（rerank API） |
| LLM | 阿里云百炼 DashScope（qwen） |
| 多模态 | 阿里云百炼 qwen3-vl-plus（商品识图 / PDF 图片转文字） |
| 缓存 | Redis（价格缓存层，TTL 7 天 + 定时刷新） |
| 鉴权 | python-jose（JWT）+ passlib/bcrypt |

## 🚀 快速开始

```bash
# 1. 安装依赖
pip install -r requirements.txt

# 2. 配置环境变量（复制 .env.example 为 .env，填入密钥）
#    DASHSCOPE_API_KEY：阿里云百炼的 API Key
#    SECRET_KEY：JWT 签名密钥（随机字符串即可）

# 3. 启动后端（端口 8000）
uvicorn app.main:app --reload --port 8000

# 4. 另开一个终端，启动前端（端口 5173）
cd frontend
npm install
npm run dev
```

浏览器打开 **http://localhost:5173** 即可使用。

## 💰 实时价格查询（数据分层架构）

价格这类**动态数据**（会随市场变化）走**实时工具**，参数/政策等**静态知识**走 RAG 知识库——两者分层，互不污染。

```
用户问"REDMI K80 Pro 多少钱"
        │
        ▼ 意图路由（LLM 判断）
        │
        ▼ 商品名归一化（LLM：小米15 → Xiaomi 15）
        │
        ▼ query_price（只查 Redis 缓存层）
        ├─ 命中 → 返回实时价（工具回答，不走 RAG）
        └─ 未命中 → 诚实告知"查不到"，绝不降级到知识库旧价
```

**为什么价格不走 RAG**：知识库是爬取时刻的快照，价格会过期；把价格从知识库剥离，即使知识库旧，价格也不会答错。

### Redis 缓存层设计

- **数据结构**：Hash（`product:price`），field=商品名，value=价格 JSON。357 个商品一个 key 管理，支持 `HGET` 取单个 / `HGETALL` 取全部
- **刷新机制**：后台线程每 **4 天**从小米官方 API 拉取最新价，`HSET` 覆盖写入（同商品永远只有一条最新数据，不堆积）
- **保鲜期**：`TTL = 7 天`，且 **TTL(7天) > 刷新周期(4天)**，价格永不过期后才刷——"主动更新 + 被动过期"双保险
- **下架清理**：全量刷新时对账，`HDEL` 删除 API 中已不存在的商品（仅全量刷新执行，防止部分刷新误删）
- **降级策略**：Redis 不可用时自动降级读本地文件快照，并在回答中标注"价格可能非最新，建议以官网为准"（来源感知：`source=redis/file`）
- **开机自启**：Redis 注册为 Windows 服务，开机自动运行

## 💡 项目亮点

- **量化评测背书（LLM-as-Judge）**：38 题端到端评测——意图路由准确率 100%、工具命中率 100%、最终回答正确率 92.1%（35/38）；检索层 14 题命中率 92.9%、MRR 0.51
- **数据分层架构**：动态数据（价格）走 Redis 实时工具，静态知识（参数/政策）走 RAG 知识库——"商品降价"不影响系统准确性，价格永远是准实时的
- **混合检索**：BM25 精确匹配 + 向量语义检索双路召回，兼顾关键词与语义
- **数据清洗链路**：源数据清洗（爬虫规则删 URL / 导航噪音词）+ 入库后 LLM 二次清洗（丢弃网页碎片、乱码），保证知识库干净
- **分块策略按格式定制**：CSV 一行一商品（保留列名、商品名与参数不分离）、TXT 按商品边界切、Markdown 按标题切——不是一刀切
- **PDF 结构化解析（多模态）**：正文/表格/图片三类分开处理——表格转 Markdown 保留行列结构、图片抠出交给视觉模型 qwen3-vl-plus 转文字、表格块补齐章节标题防"块孤岛"
- **商品图片识图（多模态）**：用户上传商品图（前端自动转 JPEG）→ qwen3-vl-plus 识别品牌/名称/参数 → 拼进问题走 RAG，识图 token/耗时计入成本监控
- **查询增强**：Multi-Query 多角度改写 + 百炼 rerank 重排，提升召回与排序质量
- **缓存一致性设计**：Redis 价格缓存用"主动刷新 + TTL 过期"双保险（TTL > 刷新周期），降级读文件时标注来源、诚实告知用户可能非最新
- **商品名归一化**：用 LLM 把中文商品名转标准英文名（小米15 → Xiaomi 15），支持中英文混合提问
- **完整的用户体系**：JWT + bcrypt + token 7 天有效（localStorage 持久化），包含注册、登录、退出、按用户隔离的会话
- **端到端全栈**：FastAPI + SQLAlchemy + Chroma + Redis + Vue 3，一个人从后端到前端全部打通
- **演示友好**：一键体验模式，鉴权代码完整保留但演示零摩擦
